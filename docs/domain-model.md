# نموذج المجال

> الكيانات، وآلات الحالة، والثوابت التي يحرسها الخادم.
> المصدر: [`src/lib/domain/types.ts`](../src/lib/domain/types.ts) و[`auction.ts`](../src/lib/domain/auction.ts).

## 1. خريطة الكيانات

```
User ──── يعرض ────▶ Listing ◀──── يزايد ──── Bid
 │                     │  │                    │
 │                     │  └──── يُعرض عليه ──── Offer
 │                     │                       │
 └──── طرف في ────▶ Order ◀─── ينشأ من ────────┘
                       ▲
                       └── مزاد رابح · شراء مباشر · عرض مقبول

Listing ──▶ ListingEvent   سجلّ أحداث دائم (مصدر الكشف والتدقيق)

User ──▶ Wallet ──▶ LedgerEntry        قيود لا تُعدَّل ولا تُحذف
           │
           └──▶ Deposit                عربون على مزاد واحد

Order ──▶ PlatformEntry                إيراد المنصّة — قيدٌ مقابل لكل ريال
Deposit ─┘                             يخرج من محفظة مستخدم
```

الوحدة الأساسية للتداول هي **الإعلان (`Listing`) = لوحة واحدة**. لا يوجد تجميع
ولا غرف ولا طوابير: كل لوحة كيان مستقل بصفحته وكشفه وحالته
([ADR-0006](adr/0006-one-plate-per-listing.md)).

## 1.5 معرّفان لكل كيان: داخليّ ومقروء

لكل كيان `id` داخليّ عشوائي (`usr_9f2c…`) و`reference` مقروء (`U26-00001`).
الأول مفتاح النظام، والثاني ما يقوله الإنسان للإنسان.

سبعة أنواع لها مراجع: المستخدم `U` · الإعلان `L` · الصفقة `S` · الدفعة `P` ·
العربون `D` · حركة المحفظة `W` · قيد إيراد المنصّة `R`.

البنية والقواعد وحدود الاستعمال في وثيقة مستقلّة:
[الأرقام المرجعية](reference-numbers.md).

## 2. المال — أعداد صحيحة دائمًا

كل المبالغ من نوع `Halalas`: **عدد صحيح من الهللات** (1 ريال = 100 هللة).
لا تُستخدم أعداد عشرية في أي عملية حسابية، لأن `0.1 + 0.2 !== 0.3` غير مقبول
في مبالغ مالية.

| الدالة | الاتجاه |
| --- | --- |
| `riyalsToHalalas(n)` | مدخلات المستخدم ← التخزين |
| `halalasToRiyals(n)` | التخزين ← العرض |
| `parseAmountInput(s)` | نص فيه فواصل أو أرقام عربية ← هللات (أو `null`) |
| `formatAmount(n)` | هللات ← `25,500` |
| `numericToHalalas` / `halalasToNumeric` | حدّ PostgreSQL `numeric(14,2)` |

القاعدة: التحويل عند الحدود فقط — عند قراءة إدخال المستخدم، وعند العرض، وعند
الكتابة في قاعدة البيانات. ما بينها هللات صحيحة.
راجع [ADR-0002](adr/0002-integer-halalas.md).

## 3. اللوحة (`Plate`)

قيمة مضمّنة داخل الإعلان لا جدول مستقل.

| الحقل | الوصف |
| --- | --- |
| `plateType` | `private` خصوصي · `transport` نقل خاص · `motorcycle` دراجة نارية |
| `arabicLetters` | حروف معتمدة فقط، مطبّعة، بحدّ `PLATE_TYPE_MAX_LETTERS` |
| `latinLetters` | المقابل اللاتيني، **يجب أن يساوي طول العربية** |
| `plateNumbers` | 1 – 4 أرقام |
| `emblem` | الشعار الأوسط، أو `custom` مع `customEmblemUrl` |

الحد الأقصى للحروف: خصوصي ونقل خاص 3، دراجة نارية 2.
خريطة الحروف موثّقة في [تصميم اللوحة](plate-rendering.md).

## 4. طرق البيع (`SaleType`)

| الطريقة | كيف تُغلق | الحقول المستخدمة |
| --- | --- | --- |
| `auction` مزاد | بانتهاء الوقت | `startingPrice`, `minimumIncrement`, `reservePrice`, `durationSeconds`, حقول التمديد, `allowCustomBid` |
| `fixed` بيع مباشر | بأول ضغطة «اشترِ الآن» | `price` |
| `offers` استقبال عروض | بقبول البائع لعرض | `minimumOffer` (0 = بلا حد) |

## 5. آلة حالة الإعلان

```
                    ┌──────────────── نشر ─────────────────┐
                    │                                      ▼
  (إنشاء) ──▶ draft ─┤                                  active
              ▲      └── حذف ──▶ (لا شيء)               │ │ │ │
              │                                         │ │ │ │
     relist ──┴──────────────────────────────┐          │ │ │ │
                                             │          │ │ │ │
   sold ◀──── مزاد بلغ الاحتياطي ─────────────┼──────────┘ │ │ │
              شراء مباشر · عرض مقبول          │            │ │ │
                                             │            │ │ │
   reserve_not_met ◀── انتهى دون الاحتياطي ───┤◀───────────┘ │ │
                                             │              │ │
   no_bids ◀──────── انتهى بلا مزايدات ───────┤◀─────────────┘ │
                                             │                │
   cancelled ◀─────── إلغاء البائع ───────────┴────────────────┘
```

- `scheduled` محجوزة لمزاد له `startsAt` مستقبلي؛ ينقله المسح الدوري إلى `active`.
- الحالات المغلقة الأربع تجمعها `CLOSED_LISTING_STATUSES`، ويختبرها `isClosedListing()`.
- التعديل (`PATCH`) ممنوع على إعلان مغلق أو عليه مزايدة مقبولة.
- الحذف (`DELETE`) ممنوع على إعلان عليه أي مزايدة أو مُباع — الإلغاء بديله.

## 6. قواعد المزايدة

كلها في [`assertBidIsValid`](../src/lib/domain/auction.ts)، وكلها تُنفَّذ على
الخادم وترمي `TradeError` برمز محدّد:

| الشرط | الرمز |
| --- | --- |
| الإعلان ليس مزادًا | `NOT_AN_AUCTION` |
| المزايد هو البائع | `OWN_LISTING` |
| المزاد لم يبدأ | `AUCTION_NOT_STARTED` |
| الإعلان غير نشط | `LISTING_NOT_ACTIVE` |
| مضى وقت النهاية | `AUCTION_ENDED` |
| المبلغ ليس صحيحًا موجبًا | `INVALID_AMOUNT` |
| مبلغ مخصص والمزاد يمنعه | `CUSTOM_BID_NOT_ALLOWED` |
| المزايد صاحب أعلى مزايدة أصلًا | `ALREADY_HIGHEST` |
| أقل من المطلوب | `AMOUNT_TOO_LOW` |
| مخصص وليس مضاعفًا للزيادة | `INVALID_AMOUNT` |

**المزايدة التالية المطلوبة**:

```
لا مزايدات  ⇒  startingPrice
غير ذلك     ⇒  أعلى مزايدة + minimumIncrement
```

## 7. التمديد التلقائي

يمنع القنص في الثواني الأخيرة. عند مزايدة والوقت المتبقي
`≤ extensionTriggerSeconds`:

| `extensionResetsTimer` | النتيجة |
| --- | --- |
| `true` | النهاية = الآن + `extensionDurationSeconds` (إعادة ضبط) |
| `false` | النهاية = النهاية الحالية + `extensionDurationSeconds` (تراكم) |

`extensionTriggerSeconds = 0` يعطّل الخاصية.

## 8. السعر الاحتياطي — سرّ لا يغادر الخادم

`reservePrice` **لا يظهر في أي حمولة عامة إطلاقًا**. الزائر يرى `reserveState`
المشتق فقط:

| القيمة | المعنى |
| --- | --- |
| `unknown` | لا سعر احتياطي أو لا مزايدات بعد |
| `not_met` | يوجد احتياطي ولم يُبلغ |
| `met` | بُلغ الاحتياطي |

البائع وحده يرى `reserveGap` (الفارق المتبقي) في `AccountListing`.
اختبار في `tests/unit/market-flow.test.ts` يؤكّد مفاتيح `ListingDetail`
مقابل قائمة بيضاء، فأي حقل جديد يسرّب الاحتياطي يُسقِط الاختبار.

## 9. نتيجة المزاد

```
لا مزايدات                    ⇒ no_bids
أعلى مزايدة ≥ reservePrice     ⇒ sold      (+ إنشاء Order)
أعلى مزايدة <  reservePrice     ⇒ reserve_not_met
reservePrice = 0               ⇒ sold عند وجود أي مزايدة
```

## 10. العروض (`Offer`)

`pending → accepted | declined | withdrawn`

- إرسال عرض جديد **يسحب** عرض المشتري السابق المعلّق على الإعلان نفسه، فلا
  يبقى للمشتري أكثر من عرض حيّ واحد.
- قبول عرض: يُغلق الإعلان (`sold`)، ويُنشئ `Order`، و**يرفض بقية العروض المعلّقة**.
- البائع وحده يقبل أو يرفض؛ المشتري وحده يسحب.

## 11. الطلبات (`Order`)

الصفقة ومالها: المنصّة **تحجز ثمنها أمانةً** حتى تُنقل الملكية، ثم تُفرجه
للبائع بعد خصم مستحقّاتها. التفصيل في [المحفظة والعرابين ← الضمان](wallet-and-deposits.md#الضمان--من-السداد-إلى-الإفراج).

| الحقل | الوصف |
| --- | --- |
| `source` | `auction` · `fixed` · `offer` |
| `status` | `awaiting_settlement` → `escrow_held` → `ownership_transferred` → (`disputed`) → `completed` · `refunded` · `cancelled` · `defaulted` |
| `paidAt` · `escrowAmount` | لحظة وصول المال والمبلغ المحجوز أمانةً |
| `transferDueAt` · `transferProofAt` | مهلة نقل البائع للملكية، ولحظة رفعه إثباتها |
| `confirmDueAt` | مهلة **الإدارة** للتحقّق من النقل — بانقضائها تُذكَّر ولا يتحرّك مال (والاسم من زمن كان التأكيد فيه على المشتري) |
| `disputedAt` · `disputeReason` · `disputedBy` | الاعتراض: متى ولماذا وممّن |
| `payoutLedgerEntryId` · `releasedAt` | قيد عائد البائع وختم التحويل — والقيد يمنع تكراره |
| `paymentDueAt` | نهاية مهلة السداد — بعدها تجوز المصادرة |
| `depositId` | العربون المرتبط، إن وُجد |
| `remindersSent` | علامات التذكيرات المُرسَلة (`24h` · `6h` · `overdue`) |

**لا أحد يُعلّم صفقة مكتملة.** الاكتمال صار **تحويلًا للمال** يقع بقرار الإدارة
بعد تحقّقها من نقل الملكية: البائع لا يملكه (`USE_TRANSFER_FLOW`) ولا الأدمن
يبلغه بتبديل حالة (`USE_RELEASE_FLOW`). وما بقي للبائع هو الإلغاء.

والأثر المالي مقسوم على لحظتين لا واحدة: عند **التحصيل** يُخصم عربون المشتري
وتعود عرابين بقيّة المزايدين وتُحصَّل عمولة المشتري، وعند **التحويل** يُقيَّد
عائد البائع بعد اقتطاع عمولته وضريبتها.

## 11.5 المحفظة والعرابين

نظام مالي كامل يقيّد المزايدة: `Wallet` برصيدين، و`LedgerEntry` لا يُعدَّل،
و`Deposit` بدورة حياة `held → released | forfeited | applied`.
التفصيل في وثيقة مستقلّة: [المحفظة والعرابين](wallet-and-deposits.md).

## 11.55 المدفوعات

`Payment` بحالاته الستّ و`PaymentSettings` (سجلّ واحد **بلا أي مفتاح سرّي**).
المال يدخل المحفظة من نقطة واحدة يحرسها `ledgerEntryId` ضدّ الشحن المزدوج.
التفصيل في [المدفوعات](payments.md).

## 11.56 العمولة وحساب المنصّة

`CommissionSettings` (سجلّ واحد) لكل طرف إعداده — نسبة أو مبلغ ثابت بحدّين —
وضريبة قيمة مضافة **على العمولة وحدها**. وكل ريال يخرج من محفظة مستخدم يدخل
قيدًا مقابلًا في `PlatformEntry` بحالة `settled` (محصَّل) أو مستحقّ أو
`reversedAt` (مُبطَل). التفصيل في
[العمولة والقيمة المضافة](commissions-and-vat.md).

## 11.6 الأسئلة الشائعة والإدارة

`FaqItem` بعلمَي `published` (يظهر في `/faq`) و`showOnListing` (يظهر أيضًا
أسفل صفحة المزاد)، و`AdminAccount` منفصل تمامًا عن `User`.
التفصيل في [لوحة الإدارة](admin-panel.md).

## 12. الأحداث (`ListingEvent`)

سجلّ دائم يُكتب مع كل تغيّر، ويُدفع لحظيًا في اللحظة نفسها:

`listing_published` · `bid_placed` · `bid_cancelled` · `time_extended` ·
`auction_ended` · `offer_placed` · `offer_accepted` · `offer_declined` ·
`listing_sold` · `listing_cancelled`

## 13. الحمولات العامة مقابل الداخلية

| النوع | الجمهور | يحجب |
| --- | --- | --- |
| `ListingCard` | السوق | الاحتياطي، بيانات التواصل، هويات المزايدين |
| `ListingDetail` | صفحة الإعلان | الاحتياطي (يُستبدل بـ `reserveState`)، أسماء المزايدين مقنّعة |
| `PublicBid` | الكشف | `bidderName` مقنّع عبر `maskName()` مثل «ماجد ا*****» |
| `AccountListing` | البائع لإعلانه | لا شيء — يشمل `reserveGap` و`reserveMet` |

`maskName()` يُبقي الاسم الأول كاملًا ويستبدل بقية أجزاء الاسم بأول حرف ونجوم،
ولا تُعرض أرقام الجوال في
أي حمولة عامة.

## 14. ثوابت النظام

1. المبالغ أعداد صحيحة من الهللات.
2. `reservePrice` لا يغادر الخادم.
3. الوقت المرجعي ساعة الخادم؛ العميل يعرض فقط.
4. لا يزايد أحد ولا يشتري من إعلانه.
5. لوحة واحدة لا تُباع مرّتين (قفل + منع تكرار).
6. لا يعلو مبلغ مزايدة على مبلغ لاحق (`serverSequence` متزايد).
7. المزاد ينتهي في وقته بلا حاجة إلى زائر.
8. كل قاعدة حرجة على الخادم؛ ما في العميل تحسين تجربة لا حراسة.
9. لا مزايدة في مزاد ذي عربون بلا مبلغ محجوز فعلًا من رصيد المحفظة.
10. المحجوز لا يتجاوز الرصيد، والمتاح لا يصير سالبًا.
11. قيود المحفظة لا تُعدَّل ولا تُحذف — التصحيح بقيد مضادّ.
12. لا يُضاف رصيد دفعة مرّتين مهما تكرّرت الإشعارات.
13. مفاتيح بوابة الدفع لا تُخزَّن ولا تُعرض — من البيئة وحدها.


## حسابات التواصل

لكل مستخدم `social: { tiktok, snapchat, instagram }` — اختيارية بالكامل،
تُملأ عند التسجيل أو من `/account/settings`.

**لماذا؟** لبثّ المزادات على منصّات التواصل: المنصّة تحتاج أن تنسب اللوحة إلى
صاحبها في البثّ، وأن تتواصل مع الفائز خارج المنصّة عند الحاجة.

**تُخزَّن بشكل واحد**: بلا `@`، بحروف صغيرة، بلا رابط. `normalizeSocialHandle`
يقبل ما يلصقه الناس فعلًا — `@name` و`name` والرابط الكامل — ويُخرج الاسم وحده.
بلا هذا التطبيع يصير الحساب الواحد حسابين في القاعدة، ولا يُفتح أيّهما.

وما ليس اسم حساب صالحًا (حروف عربية، مسافات، أقصر من حرفين) يعود `null` بدل أن
يُخزَّن نصًّا لا يُفتح.

| المنصّة | الرابط المبني |
| --- | --- |
| تيك توك | `tiktok.com/@{handle}` |
| سناب شات | `snapchat.com/add/{handle}` |
| إنستقرام | `instagram.com/{handle}` |
