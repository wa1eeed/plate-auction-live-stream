# التشغيل والنشر

> ما يلزم لتشغيل المنصّة في بيئة حقيقية، وما يختلف عن مشروع Next عادي.

## 1. الفرق الجوهري

**لا يعمل بـ `next start`.** التطبيق يُشغَّل بخادم مخصّص
([`server.mjs`](../server.mjs)) يستضيف Next وWebSocket في العملية نفسها.

```bash
pnpm build
NODE_ENV=production node server.mjs   # وهو ما يفعله pnpm start
```

يترتّب على هذا:

- **بيئة Node طويلة العمر مطلوبة.** المنصّات عديمة الحالة (serverless / edge)
  لا تصلح: المقابس تعيش في ذاكرة العملية، والمسح الدوري يحتاج مؤقّتًا مستمرًّا.
- **وسيط الشبكة يجب أن يمرّر ترقية WebSocket** على `/ws`.
- **نسخة واحدة** في الوضع الحالي — انظر القسم 7.

## 2. المتطلبات

| | |
| --- | --- |
| Node.js | 20 فأعلى |
| pnpm | 9 فأعلى |
| الذاكرة | ~512MB تكفي وضع الذاكرة الحالي |
| المنافذ | `PORT` (افتراضيًا 3000) |

## 3. متغيّرات البيئة للإنتاج

```bash
SESSION_SECRET=$(openssl rand -base64 48)   # إلزامي
NEXT_PUBLIC_APP_URL=https://example.com     # النطاق الحقيقي
DEMO_MODE=false                             # لا بيانات تجريبية
PORT=3000
HOST=0.0.0.0
BID_RATE_LIMIT_WINDOW_MS=10000
BID_RATE_LIMIT_MAX=6
PLATFORM_DATA_DIR=/app/data                 # مجلّد دائم — انظر القسم 4

# قاعدة البيانات — بوجوده تبقى البيانات بعد كل نشرة، وبغيابه تُمحى
DATABASE_URL=postgres://...                 # الرابط **الداخليّ** في كوليفاي
DEMO_ADMIN_EMAIL=you@example.com            # حساب الإدارة يُبنى منهما كل إقلاع
DEMO_ADMIN_PASSWORD=                        # اضبطه — الافتراضيّ في المستودع
VAPID_PUBLIC_KEY=                           # بلا المفتاحين لا إشعارات دفع
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:you@example.com        # https: أو mailto: — وإلّا عُطّل الدفع

# تخزين الوسائط — على قرص الخادم
MEDIA_DIR=                                  # تجاوزٌ يدويّ — افتراضُه /app/data/media
```

> **ولا مفاتيحَ خارجية**: البنرات والستوريز وملفّات المستخدمين تسكن
> `$PLATFORM_DATA_DIR/media` وتُقدَّم من `/api/media/`.

### ⚠️ وشرطٌ واحد لا يُترك

**`Coolify → Storages → Volume Mount: /app/data`**

وبلاه يكون المجلَّد داخل الحاوية، والحاوية تُستبدل مع كلّ نشرة — فتضيع
الوسائط والإعدادات معًا، **وتبقى صفوفُها في القاعدة** فتُعرض صورٌ مكسورة بلا
رسالةِ خطأ واحدة.

ويُقاس عند كلّ إقلاع، فاقرأ أوّلَ سطرٍ في السجلّ:

```
[media] الحجم الدائم مربوط على /app/data          ← سليم
[media] ⚠ /app/data ليس حجمًا دائمًا …            ← اربطه الآن
```

التفصيل في [تخزين الوسائط](media-storage.md).

### ⚠️ ومهلةُ البوّابة — الفخُّ الذي كلّف يومًا

**Traefik v3 يضع `respondingTimeouts.readTimeout` على ٦٠ ثانية افتراضًا**
(وv2 كان بلا حدّ). و«قراءةُ الطلب» تشمل **جسمه**، فكلُّ رفعٍ يتجاوز الدقيقة
يُقتل — مهما كان حجمه صغيرًا، لأنّ الفيصل **الزمن لا الحجم**.

وأثرُه في اللوحة: الوصلة تموت والمتصفّح ما زال يضخّ، فلا يصل ردٌّ — فيُقرأ
«تعذّر الاتّصال بالخادم» والشبكةُ سليمة والخادمُ يعمل. ولا شيء في سجلّ
التطبيق إلّا `[Error: aborted] { code: 'ECONNRESET' }` بلا سطر `[api]`.

فيُضاف في `Servers → localhost → Proxy → Configuration` داخل `command:`:

```yaml
- '--entryPoints.http.transport.respondingTimeouts.readTimeout=600s'
- '--entryPoints.https.transport.respondingTimeouts.readTimeout=600s'
```

ثمّ **Restart Proxy**. ولا يُضاف `writeTimeout`: افتراضُه بلا حدّ، ووضعُ رقمٍ
له يُنشئ قيدًا جديدًا على تحميل الفدّيو **من** الخادم بدل أن يرفعه.

**ويُقاس من الخارج** — رفعٌ بطيءٌ متعمَّد يتجاوز الدقيقة:

```bash
curl -s -o /dev/null -w 'status=%{http_code} رُفع=%{size_upload} الزمن=%{time_total}s\n' \
  -X POST https://mazad.nx.sa/api/admin/media \
  -F purpose=story -F 'file=@big.bin;type=video/mp4' --limit-rate 50k --max-time 300
```

| الردّ | الحكم |
| --- | --- |
| `502` عند ٦٠ ثانية، والمرفوع ناقص | المهلة قائمة |
| `401` بعد الزمن كاملًا، والمرفوع تامّ | المهلة رُفعت — و`401` صحيحة لأنّ الأمر بلا جلسة |

> **والدرسُ أعمُّ من الرقم**: عطلٌ يظهر في المتصفّح ولا يخلّف سطرًا في سجلّ
> التطبيق **ليس في التطبيق**. وقد طُورد هذا في الكود وفي R2 وفي CORS يومًا
> كاملًا، وكان في طبقةٍ لم تُسأل — لأنّ أحدًا لم يقس الزمن.

`SESSION_SECRET` يوقّع الجلسات **ويحمي مسار المسح الداخلي**. في الإنتاج يرمي
التطبيق عند أول عملية توقيع أو تحقّق إن كان مفقودًا أو أقصر من 16 حرفًا، فأول
طلب مصادقة يفشل صراحةً. تحقّق منه قبل توجيه الحركة لا بعده.

## 3.5 قاعدة البيانات — خدمةٌ مستقلّة لا جزءٌ من التطبيق

**بلا `DATABASE_URL` تعيش البيانات في ذاكرة العملية وتُمحى مع كلّ نشرة.** وهي
تُرى من كلّ جهاز — لأنّ الجميع يخاطب البرنامج نفسه — فتبدو محفوظة. و«مشتركة»
ليست «باقية».

في كوليفاي:

1. المشروع ← **+ New** ← **Database** ← **PostgreSQL 16** ← **Deploy**
2. انسخ **Postgres URL (internal)** — الداخليّ لا الخارجيّ، فلا يمرّ المال
   بالإنترنت العامّ
3. ضعه في متغيّرات **التطبيق** باسم `DATABASE_URL`

ولا يُضاف شيءٌ على القاعدة نفسها: كوليفاي يهيّئها كاملةً. **والترحيل يجري
تلقائيًّا** عند إقلاع التطبيق — لا أمرَ تكتبه.

ومتى ضُبط الرابط **لم تعد `PLATFORM_DATA_DIR` لازمة**: الإعدادات تنتقل إلى
القاعدة مع كلّ ما عداها. التفصيل في [قاعدة البيانات](database.md).

> **فعّل النسخ الاحتياطيّ** من لوحة القاعدة أوّلَ شيءٍ بعد إنشائها: القاعدة
> تحفظ من إعادة النشر ولا تحفظ من الخطأ — أمرُ حذفٍ خاطئ، أو قرصٌ يتلف.

## 4. إعدادات تبقى بعد النشر

المخزن في الذاكرة، فكلّ نشرةٍ تبدأ من البذرة: يُبدَّل اسم المنصّة ولونها
وشعارها، وتُكتب صفحاتها، وتُضبط عمولتها وبوابات دفعها — ثمّ يعود ذلك كلّه
افتراضيًّا لأنّ العملية أُعيد تشغيلها. وهو ما **لا يُكتشف إلّا بعد النشر**،
فيُظنّ الحفظُ نفسه معطّلًا.

```bash
PLATFORM_DATA_DIR=/app/data     # مجلّد دائم — بلا ضبطه لا حفظ
```

ما يُكتب هو `PLATFORM_DATA_DIR/settings.json`، ويُقرأ **فوق البذرة** عند
الإقلاع: البذرة أوّلًا ليأخذ كلُّ حقلٍ جديد افتراضيَّه، ثمّ يُلبَس ما حُفظ. وما تضبطه الإدارة
مشروحٌ في [الهويّة والأرشفة وصفحات المنصّة](brand-and-pages.md#6-الثبات-بعد-إعادة-النشر).

### ما يُحفظ وما لا يُحفظ

| يُحفظ | لا يُحفظ |
| --- | --- |
| `brandSettings` · `pageSettings` · `faq` | المستخدمون |
| `auctionSettings` · `commissionSettings` | الإعلانات والمزايدات والسوم |
| `paymentSettings` · `taxSettings` | الصفقات والمحافظ والقيود |

الخطّ بين العمودين مقصود: هذه **إعدادات** تضبطها الإدارة، وتلك بيانات تشغيل
تُولَد من البذرة. وحفظُ الثانية في ملفٍّ يجعله قاعدة بيانات ناقصة لا ملفَّ
إعدادات — وذلك عملٌ آخر بأدواته ([ADR-0003](adr/0003-store-abstraction.md)).

### ضماناته

- **الدمج بالشريحة لا بالحقل**: شريحةٌ محفوظة تحلّ محلّ نظيرتها كاملةً. ولو
  دُمجت حقلًا حقلًا لبقيت حقولٌ حُذفت من الإعدادات حيّةً في الملفّ إلى الأبد.
- **الكتابة ذرّية**: يُكتب ملفٌّ مؤقّت ثمّ يُنقل مكانه، فانقطاعٌ في أثناء
  الكتابة لا يترك ملفًّا نصفَ مكتوب يُسقط الإقلاع التالي.
- **ملفٌّ تالف يُتجاهل**: تُستعمل البذرة، ويُكتب فوقه عند أوّل حفظ. الإقلاع لا
  يسقط بملفّ إعدادات.
- **تعذّر الحفظ لا يُسقط طلبًا نجح**: قرصٌ ممتلئ أو مسارٌ بلا صلاحية يترك الضبط
  في الذاكرة لهذه النشرة وحدها.
- **وبلا ضبطٍ لا حفظ**: في التطوير والاختبار لا نريد ملفًّا يعيش بين التشغيلات
  فيُفسد بذرةً يُعتمد عليها، ولا كتابةً في مسارٍ لم يختره أحد.

**والشاشة تقول ذلك.** `settingsPersisted()` تُقرأ في `/admin/settings`: فبلا
مجلّدٍ دائم يظهر تنبيهٌ يقول إنّ ما يُضبط لا يبقى بعد إعادة التشغيل، ويسمّي
المتغيّر. فعودةُ الضبط افتراضيًّا لا تُقرأ **عطلًا في الحفظ**.

### الربط

الحاوية تضبط المتغيّر وتُعلن الحجم:

```dockerfile
ENV PLATFORM_DATA_DIR=/app/data
VOLUME ["/app/data"]
```

لكنّ حجمًا مجهولًا (anonymous) يُستبدل مع الحاوية في أغلب المنصّات. **اربط
مجلّدًا دائمًا بالمسار صراحةً** وإلّا عاد الضبط افتراضيًّا مع كل نشرة:

- **Coolify** → Storages → Volume Mount: `/app/data`
- **docker compose** → مضبوطٌ في [`docker-compose.yml`](../docker-compose.yml):
  حجمٌ مسمّى `plate-data` مربوطٌ بـ`/app/data`.

```yaml
services:
  app:
    volumes:
      - plate-data:/app/data

volumes:
  plate-data:
```

والحجم المسمّى يبقى بعد `docker compose down` وبعد إعادة البناء — يُمحى بـ`-v`
وحدها. أمّا المجهول فيُنشأ باسمٍ عشوائي مع كلّ حاوية.

## 5. وسيط الشبكة

يجب تمرير ترويسات الترقية على `/ws`، وإلا لم يعمل الاتصال اللحظي (وستسقط
الواجهة إلى الجلب الدوري كل 8 ثوانٍ — تعمل، لكن بتأخير).

### nginx

```nginx
location /ws {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;    # أطول من حدّ الصمت (45 ثانية)
}

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

### Caddy

```
example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Caddy يمرّر الترقية تلقائيًا.

**احجب `/api/internal/sweep`** عن الإنترنت العام. هو محمي بالمفتاح، لكن حجبه
على مستوى الشبكة طبقة ثانية بلا تكلفة:

```nginx
location /api/internal/ { deny all; }
```

الخادم يستدعيه عبر `127.0.0.1` فلا يتأثّر بالحجب.

## 6. HTTPS

مطلوب: كوكي الجلسة يحمل `Secure` في الإنتاج فلا يُرسل على HTTP، أي أن تسجيل
الدخول لن يعمل أصلًا بلا HTTPS. صفحة `https` تفتح المقبس على `wss://` تلقائيًا.

## 7. التوسّع الأفقي

الوضع الحالي **نسخة واحدة**. ثلاثة أشياء تعيش في ذاكرة العملية:

| ما | التأثير | العلاج |
| --- | --- | --- |
| `__auctionStore` | البيانات كلها | تنفيذ `AuctionStore` على PostgreSQL ([ADR-0003](adr/0003-store-abstraction.md)) |
| `__plateRealtime` | النشر يصل لمقابس هذه النسخة فقط | ناقل مشترك (Redis pub/sub) داخل `publishRealtime` |
| `__rateBuckets` | الحدّ يتضاعف بعدد النسخ | مخزن مشترك |

كذلك المسح الدوري: مع عدة نسخ سينفّذه كلٌّ منها. `finalizeDueAuctions` تعمل
على حالة الإعلان فلا تُنشئ طلبًا مكرّرًا (تفحص وجود طلب سابق)، لكن الأنظف عند
التوسّع نقله إلى عامل واحد أو قفل موزّع.

## 8. المراقبة

نقاط تستحق التتبّع:

- عدد المقابس المتصلة: `getRealtimeRegistry().sockets.size`.
- استجابة `POST /api/internal/sweep` تعيد `{ finalized: n }` — عدد الإعلانات
  التي أُنهيت في الدورة.
- نسبة حالة `offline` في العميل مؤشّر على وسيط شبكة لا يمرّر الترقية.

## 9. النسخ الاحتياطي

بوجود `DATABASE_URL` كلُّ شيءٍ في القاعدة — فالنسخ الاحتياطي نسخُها وحدها.
فعّله من لوحة الخدمة في كوليفاي، وتحقّق من **استعادةٍ** واحدة على الأقل: نسخةٌ
لم تُستعَد قطّ ليست نسخة، بل ظنٌّ بها.

وبغير رابط — أي على الذاكرة — بيانات التشغيل غير دائمة أصلًا، ويبقى
`PLATFORM_DATA_DIR/settings.json` وحده خارجها (القسم 4).

## 9.5 «no available server» — الحاوية ماتت، لا الوكيل

هذا ردُّ الوكيل العكسي حين **لا خادمَ صحيًّا خلفه**. والبناءُ الناجح لا ينفيه:
البناء والتشغيل مرحلتان مختلفتان في الصورة، وما ينقص الثانية لا يظهر في سجلّ
الأولى.

```bash
docker logs <الحاوية> | head -30      # أوّل السجلّ فيه السبب، لا آخره
```

| ما تقرؤه | ما يعنيه |
| --- | --- |
| `ERR_MODULE_NOT_FOUND` | ملفٌّ يحتاجه الإقلاع ليس في مرحلة التشغيل — انظر [قاعدة البيانات §٩٫٧](database.md) |
| `[db] فشل الترحيل` | القاعدة غير قابلة للوصول أو الرابط خطأ — والخروج متعمَّد: لا خدمةَ على مخطَّطٍ ناقص |
| `SESSION_SECRET` | المتغيّر الإلزاميّ غائب |
| لا سجلّ أصلًا | الصورة لم تُبنَ بعد، أو الحاوية في حلقة إعادة تشغيل |

## 9.6 بناءٌ يسقط بلا سطر خطأ — اقرأ الذاكرة لا الكود

```
5.581    ▲ Next.js 15.5.24
5.976  ELIFECYCLE  Command failed.
```

**`Command failed.` بلا رمز خروج** — وهذا فارقٌ يُغفَل: pnpm يكتب
`Command failed with exit code N` حين يخرج البرنامج بنفسه، ويكتبها **مجرّدةً**
حين يُقتل بإشارة. ومع طباعة الترويسة ثمّ الموت بلا سطر خطأ واحد، فالقاتل
نظامُ التشغيل لا المترجم: الأخطاء تُطبع، والقتلُ لا يُطبع.

وسببُه أنّ الخادم يبني **فوق ما يشغّله**: المنصّة الحيّة وPostgres وكوليفاي،
ثمّ `next build` يطلب ذاكرةً فلا يجد.

```bash
# على الخادم — يحسم الأمر
sudo dmesg | grep -i "killed process" | tail -5
```

| العلاج | الأثر |
| --- | --- |
| **ملفّ مبادلة (swap)** على الخادم | الأنجع — يُنشأ مرّةً ويبقى |
| `NODE_OPTIONS=--max-old-space-size` في `Dockerfile` | تجمع عقدةُ القمامة بدل أن تنمو — يُبطئ ولا يُسقط |
| `experimental: { cpus: 1, workerThreads: false }` | Next يفتح عاملًا لكلّ نواة افتراضًا، وخادمٌ صغير قد تكثر نواتُه وتقلّ ذاكرتُه |
| بناءٌ في CI ودفعُ الصورة إلى سجلّ | الأنظف — الخادم يسحب ولا يبني |

> **ولماذا ظهر الآن؟** لأنّ البناء ثقُل: إضافةُ `middleware.ts` تضيف **هدف
> ترجمةٍ كاملًا** لبيئة الحافّة. فما كان يمرّ بالكاد صار يتجاوز السقف.

### وصورةٌ أخرى منه: يسقط عند `COPY` قبل أن يبدأ البناء

```
#16 [build 4/6] COPY --from=deps /app/node_modules ./node_modules
… ثمّ انقطاعٌ بلا سطر خطأ، و`exit code 255`
```

وهذه **ليست** ذاكرةَ `next build`: الطبقة لم تُبنَ بعد. و`node_modules`
كاملةً نحو **٦١٥ ميغابايت**، ونسخُها يطلب قرصًا وذاكرةً معًا.

> ⚠️ **ولا يُفترض أنّها الذاكرة.** قِيس خادمُ المنصّة في ٢٤ سبتمبر بعد سقوطٍ
> من هذه الصورة فكان فيه **١١ غيغا متاحة** و**١٦٧ غيغا حرّة** و`dmesg` بلا
> قتيل — فالأوامر الثلاثة أدناه تُقاس **قبل** أيّ علاج، لا بعده.

**يُحسم بثلاثة أوامر على الخادم:**

```bash
df -h /                                      # قرصٌ ممتلئ؟
free -h                                      # ذاكرةٌ وهل ثمّة مبادلة
sudo dmesg | grep -i "killed process" | tail -5   # من قُتل ومتى
```

**١) إن كان القرص**: يُفرَّغ ما يتراكم من البناء — ولا يُمسّ حجم.

```bash
docker builder prune -af    # ذاكرة البناء المؤقّتة — أكبر ما يتراكم
docker image prune -af      # صورٌ لا تستعملها حاوية
```

> ⚠️ **ولا يُكتب `--volumes` أبدًا.** `docker system prune --volumes` يمحو
> `/app/data` وقاعدة البيانات معها. والأمران أعلاه لا يمسّان حجمًا.

**٢) وإن كانت الذاكرة**: ملفُّ مبادلة — يُنشأ مرّةً ويبقى بعد الإقلاع.

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h                                      # يُقرأ Swap: 4.0Gi
```

**٣) والأنظف — وهو المعمولُ به الآن**: تُبنى في البوّابة وتُدفع إلى
`ghcr.io`، ويسحبها الخادم بلا أن يبني. وظيفةُ `image` في
[`ci.yml`](../.github/workflows/ci.yml) تفعل ذلك في كلّ دفعةٍ إلى `main`.

```
ghcr.io/wa1eeed/plate-auction-live-stream:latest      ← ما يسحبه الخادم
ghcr.io/wa1eeed/plate-auction-live-stream:<sha>       ← لتثبيت نشرةٍ أو الرجوع
```

والصورةُ عامّة، فلا اعتمادَ يُضبط في كوليفاي. وما يلزم ضبطُه فيه:

| الحقل | القيمة |
|---|---|
| المصدر | صورة دوكر (لا مستودع ولا Dockerfile) |
| المنفذ | `3000` |
| التخزين الدائم | `/app/data` — **يبقى كما هو** |
| متغيّرات التشغيل | تبقى كما هي: `DATABASE_URL` و`SESSION_SECRET` و`PLATFORM_DATA_DIR` وغيرها |

> ⚠️ و`NEXT_PUBLIC_APP_URL` **وحده** لا يُضبط في كوليفاي بعد اليوم: يُحقن في
> حزمة المتصفّح وقت البناء، فيُخبز في البوّابة. وتغييرُ النطاق يُغيَّر في
> متغيّر المستودع `NEXT_PUBLIC_APP_URL` على GitHub، لا في لوحة النشر.

> ⚠️ **ولا يُنشأ مصدرٌ جديد بلا نقل التخزين الدائم.** مورِدٌ جديد بلا ربط
> `/app/data` يُقلع بإعداداتٍ فارغة — تذهب الهويّةُ والصفحاتُ والعمولة،
> ويبقى ما في قاعدة البيانات وحده.

وإن أقلع الخادم فأوّل سطرين: `[db] …ترحيلًا` ثمّ `▲ جاهز على …`.

## 10. قائمة فحص النشر

- [ ] `SESSION_SECRET` عشوائي طويل خاص بالبيئة
- [ ] `DEMO_MODE=false`
- [ ] `NEXT_PUBLIC_APP_URL` = النطاق الحقيقي
- [ ] HTTPS مفروض
- [ ] الوسيط يمرّر ترقية WebSocket على `/ws`
- [ ] `/api/internal/*` محجوب خارجيًا
- [ ] `PLATFORM_DATA_DIR` مضبوط ومربوط بمجلّد **دائم** (وإلّا ضاع ضبط الإدارة مع كل نشرة)
- [ ] مدير عمليات يعيد التشغيل عند السقوط (systemd / PM2 / حاوية)
- [ ] `DATABASE_URL` يشير إلى القاعدة، والنسخ الاحتياطي **مفعَّل**
- [ ] بعد أوّل نشرة: السجلّ يبدأ بـ`[db] …` ثمّ `▲ جاهز على …`
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm test:e2e` كلها خضراء
