# Handoff: لوحة الإدارة — سوق تداول اللوحات

> تعليمات تنفيذ لـ Claude Code لبناء لوحة الإدارة **مطابقة 100٪** للتصميم. `Admin Panel.dc.html` هو **المرجع النهائي**؛ عند أي تعارض بين هذا النص والملف يُقدَّم الملف.
> اللوحة تشترك مع التطبيق والويب في الهويّة والمكوّنات وقواعد المجال — اقرأ `../app/README.md` (§2 الرموز، §3 مكوّن اللوحة، §6 قواعد المجال) و`reference/admin-panel.md` (توثيق صلاحيات المنصّة الحالية).

## 1. قواعد عامّة

- **RTL**، خط `"IBM Plex Sans Arabic"` (700 للعناوين والأرقام) + `tabular-nums` لكل رقم ومبلغ ومرجع. Arial للّوحات فقط.
- الألوان: نفس رموز المنصّة — الأخضر `#006C35` ودرجاته، والأحمر `#a3261b` (شارات العدّ `#c0392b`) للمتعثّر والقرارات الهدّامة، وsage للمنجز.
- الأسطح: الخلفية `--color-neutral-100`، البطاقات `#fff` بحدّ 1px وانحناء 16، الأزرار انحناء 9–10 (لوحة عمل لا تسويق — أقلّ استدارة من التطبيق عمدًا).
- **نقطة التوقّف 1080px**: فوقها قائمة جانبية ثابتة 264px؛ تحتها درج جانبي (`drawerIn .28s`) وزرّ القائمة يحمل مجموع الشارات.
- **كل قرار مالي أو هدّام**: نافذة تأكيد تشرح الأثر **بالأرقام**، و**سبب إلزامي** (5 أحرف+) يُكتب في سجلّ التدقيق مع المنفّذ والوقت (Timestamp كامل 12 ساعة). المصادرة والتحويل تقبل التراجع خلال `undoH` ساعة.
- **الرقم المرجعي يُطابَق تامًّا** في البحث: `U26-` مستخدم، `L26-` إعلان، `S26-` صفقة، `D26-` عربون، `P26-` دفعة، `INV-` فاتورة.
- `prefers-reduced-motion` يوقف الحركات.

## 2. القالب

- **القائمة الجانبية** (داكنة `neutral-900`): الشعار + «لوحة الإدارة» · المجموعات: (المؤشرات) · **التشغيل**: الإعلانات، الصفقات، السوم، المستخدمون · **المال**: العرابين، المدفوعات، حركات المحافظ · **المحاسبة**: إيرادات المنصّة · **النظام**: الإشعارات الجماعية، واجهة الرئيسية، الأسئلة الشائعة، الإعدادات، سجلّ التدقيق. النشط أخضر ممتلئ. **شارات حمراء نابضة (`ping 1.8s`)** على: الصفقات (مهلة منقضية + اعتراض + تحقّق نقل)، العرابين (قابلة للمصادرة)، المدفوعات (حوالات معلّقة)، الإعلانات (موقوفة). الأسفل: المشرف + «جلسة إدارية منفصلة» + «خروج».
- **الشريط العلوي** (64px، ثابت، blur): زرّ القائمة (لوحي) · **زرّ البحث ⌘K** · **جرس التنبيهات** (بمجموع الشارات، يفتح قائمة منسدلة بنفس بنود طابور القرارات) · «عرض السوق ↗».
- **⌘K / Ctrl+K**: نافذة بحث مركزية؛ نتائج بنوعها ونصّها ومرجعها؛ Esc يغلق.
- **Toast** أسفل المنتصف 3.2 ثانية: أخضر داكن نجاح، أحمر تحذير، داكن معلومة.

## 3. الصفحات

1. **الدخول** (`login`): جلسة منفصلة عن المستخدمين. البريد الإداري + كلمة المرور (8+) → **التحقّق الثنائي** 6 خانات (تطبيق مصادقة) → ينتقل تلقائيًا ويُسجَّل `admin.login`. لوحة يسرى داكنة بشعار «كل قرار مالي بسبب مكتوب، وكل سبب في السجلّ.»
2. **المؤشرات** (`dash`): تحيّة + «لديك N أمور تحتاج قرارك» · 3 بطاقات أسئلة: **كم يجري؟** (مزادات، مزايدات اليوم، نشطون) · **أين المال؟** (محجوز أمانةً، عرابين، حوالات معلّقة) · **إلى أين نمضي؟** (قيمة الصفقات، الإيراد، المكتملة) — كل سطر يفتح صفحته. **طابور القرارات** مرتّب (1 أحمر: مهلة منقضية، اعتراض · 2 برتقالي: تحقّق نقل · 3: حوالة، موقوف)، كل بند بلوحته ووسمه وزرّ إجرائه. مخطّط 14 يومًا · ينتهي قريبًا (مع حالة الاحتياطي) · ملاحظات ذكية.
3. **الصفقات** (`orders`): تبويبات **بانتظار قرارك / تحت الإجراء / مكتملة أو مغلقة**. البطاقة: اللوحة، المرجع، وسم المرحلة، المصدر والطرفان، القيمة والعربون والمهلة (أحمر إن تأخّرت)، **سكّة المحطّات الخمس**، ثم الإجراء حسب الحالة:
   - مهلة منقضية: «صادر وأعد الإرساء على التالي» / «أعد الإرساء بلا مصادرة».
   - اعتراض: السبب + «استرداد للمشتري» / «حسم للبائع».
   - تحقّق النقل: ملفّ الإثبات PDF + «تحقّقت — حوّل للبائع».
4. **العرابين** (`deposits`): محجوزة/محسومة. المصادرة **فقط** بعد انقضاء المهلة؛ غيرها «🔒 لا إجراء متاح» مع السبب.
5. **المدفوعات** (`payments`): حوالات بانتظار التحقّق (المستخدم، البنك، المرجع، العمر) + ارفض / أكّد. «لا يُضاف رصيد دفعة مرّتين».
6. **الإعلانات** (`listings`) + **تفاصيل الإعلان** (`listing`): بطاقات اللوحة عنوانها، 4 تبويبات. التفاصيل: اللوحة كبيرة، البلاغ، **الاحتياطي السرّي ظاهر للإدارة**، المشاركون **بأسمائهم الصريحة** وأرقام عضويتهم، الإيقاف (يفكّ العرابين ويُشعر) / إعادة العرض.
7. **المستخدمون** (`users`) + **ملف 360°** (`user`): جدول (الاسم، المعرّف، المدينة، الرايات، رقم العضوية، الرصيد، المحجوز، المتاح، الصفقات). الملف: **رقم العضوية بارز ينسخ**، الإحصاءات، تبويبات الصفقات/المال/اللوحات، «تسوية إدارية» (قيد مقابل — القيود لا تُعدَّل ولا تُحذف).
8. **السوم** (`offers`): للقراءة فقط.
9. **إيرادات المنصّة** (`revenue`): المحصّل · الضريبة المستحقّة (مفصولة) · المستحقّ غير المحصّل · قيود بحالاتها (محصّل/مستحقّ/مُبطَل).
10. **حركات المحافظ** (`transactions`): قيود بالمستخدم والمبلغ الملوّن والوقت.
11. **الإشعارات الجماعية** (`push`): الجمهور (5 شرائح بأعدادها) · العنوان (50) والنص (150) بعدّاد · الوجهة عند الضغط · الآن/جدولة · **معاينة شاشة القفل حيّة** · «أرسل لجهازي أولًا» / «أرسل» (نافذة سبب) · سجلّ آخر ما أُرسل (المستلمون ونسبة الفتح). يصل لمن فعّل قناة التسويق فقط.
12. **واجهة الرئيسية** (`home`) و**الأسئلة الشائعة** (`faq`): بطاقات بشارات حالة النشر · نموذج إضافة (قصة/بنر، العنوان، منطقة الصورة 1200×400، البداية والنهاية) · سؤال جديد (السؤال، الجواب، رايات الظهور مزاد/مباشر/سوم).
13. **الإعدادات** (`settings`) — تبويبات:
   - **قواعد المزاد**: العربون (نسبة، حدّ أدنى، حدّ أعلى)، مهلة السداد، نسبة المصادرة، مهلة التراجع، بدء التمديد ومدّته + **معاينة حيّة**. تُنسخ القواعد إلى كل إعلان لحظة نشره.
   - **العمولة والضريبة**: المشتري 2٪، البائع 2.5٪، الضريبة 15٪ على العمولة.
   - **الدفع**: مفاتيح Tap (مقنّعة)، بنك وآيبان المنصّة، حالة الاتصال وآخر Webhook، **تجميد المدفوعات الصادرة (طوارئ)**.
   - **التطبيق والمتاجر**: iOS (Bundle ID، Apple App ID، Team ID، رابط المتجر) · Android (Package name، SHA-256، رابط المتجر) · الإصدار، رقم البناء، **أدنى إصدار مدعوم = تحديث إجباري** + رسالته · الروابط العميقة (نطاق Universal/App Links، Scheme). يولّد الخادم منها `apple-app-site-association` و`assetlinks.json` وقيم `capacitor.config`.
   - **FCM والإشعارات**: Project ID، Sender ID، Web API Key، VAPID · رفع حساب الخدمة (HTTP v1)، `google-services.json`، `GoogleService-Info.plist` · APNs (Key ID، Team ID، مفتاح `.p8`) · **القنوات** بمفاتيح ومعرّفاتها: `auction_updates`, `outbid`, `ending_soon`, `deal_updates`, `chat_message`, `broadcast` · **محادثة نقل الملكية**: أقصى مرفق 10MB، أقصى صوتية 120 ثانية، الاحتفاظ 5 سنوات — **FCM يحمل تنبيهًا فقط (data message بمعرّف الصفقة)، لا نصّ الرسالة ولا المرفق** · «أرسل إشعارًا تجريبيًا لجهازي».
   - **التخزين R2 (Cloudflare)**: Account ID، S3 Endpoint، Access Key، Secret · بوكت الإنتاج والتجربة، نطاق CDN العام، صلاحية الرابط الموقّع (15 دقيقة) · قيود الرفع (صورة 8MB، PDF 10MB، الأنواع، CORS يشمل `capacitor://localhost`) · **المجلّدات**: `listings/` `home/` `avatars/` عامّة عبر CDN · `proofs/` `chat/` `invoices/` **خاصّة بروابط موقّعة** · الرفع من العميل بروابط PUT موقّعة يصدرها الخادم، المفاتيح لا تصل للعميل · «افحص الاتصال».
   - **الهويّة**: الاسم، اللون (4 خيارات)، الشعار.
   - **الأرشفة**: العنوان (60) والوصف (160) بعدّاد يحمرّ عند التجاوز، **معاينة نتيجة البحث**، مفتاحا الأرشفة وقراءة مساعدات الذكاء الاصطناعي (GEO).
   - كل حفظ عبر نافذة سبب → سجلّ التدقيق.
14. **سجلّ التدقيق** (`audit`): الفعل (`order.release`, `deposit.forfeit`, `payment.confirm`, `listing.suspend`, `settings.*`, `push.broadcast`, `fcm.test`, `r2.test`, `admin.login`…) · المرجع · السبب · المنفّذ · الوقت.

## 4. تطابق مسار العمليات مع التطبيق والويب (مُلزِم)

الأدمن يرى **نفس** الصفقة التي يراها المستخدم بنفس المراحل والمحطّات، ويقسّمها بالاستثناء:

| المرحلة (المصدر الواحد) | المستخدم يرى | الأدمن يرى | تبويب الأدمن |
| --- | --- | --- | --- |
| `pay` | بانتظار السداد (المشتري) | بانتظار السداد | تحت الإجراء |
| `overdue` | — (انقضت المهلة) | انقضت مهلة السداد → مصادرة/إعادة إرساء | **بانتظار قرارك** |
| `id` | أكّد بياناتك (المشتري) | بانتظار بيانات المشتري | تحت الإجراء |
| `transfer` | دورك: انقل الملكية (البائع) | نقل الملكية — الدور على البائع | تحت الإجراء |
| `review` | الإدارة تتحقّق | تحقّق من النقل → «حوّل للبائع» | **بانتظار قرارك** |
| `disputed` | التحويل مجمّد | اعتراض مفتوح → استرداد/حسم | **بانتظار قرارك** |
| `done` | اكتملت | مكتملة | مكتملة أو مغلقة |
| `cancelled` | ملغاة قبل السداد | ملغاة قبل السداد | مكتملة أو مغلقة |
| `defaulted` · `refunded` | — | متخلّفة · مستردّة | مكتملة أو مغلقة |

- **السكّة الخماسية** «طلب · سداد · نقل · تأكيد · تم» واحدة في الأماكن الثلاثة: المنجز sage، الحالي أخضر داكن، المتعثّر أحمر.
- **حالات العربون** واحدة: `held` محجوز · `released` عاد للمحفظة · `forfeited` مُصادَر · `applied` خُصم من الصفقة.
- **التقسيم مختلف عمدًا**: المستخدم «بانتظار ردّك / تحت الإجراء / مكتملة» حسب **دوره**؛ الأدمن «بانتظار قرارك / تحت الإجراء / مكتملة» حسب **ما تعثّر**.
- كل قرار أدمن يغيّر ما يراه المستخدم فورًا ويرسل إشعاره عبر قناة `deal_updates`.

## 5. الحركة
`fadeUp` (الصفحات والنوافذ 0.2–0.35s) · `ping` (الشارات المنتظِرة) · `drawerIn` (الدرج) · hover البطاقات `--shadow-md` · المفاتيح `.2s`.

## 6. قائمة القبول
- [ ] كل صفحة وتبويب ونافذة أعلاه مطابقة للّقطات وللنموذج عند 1440 و1024 و390px.
- [ ] لا قرار مالي بلا سبب، وكلها في سجلّ التدقيق.
- [ ] الشارات تنقص فور إنجاز القرار.
- [ ] جدول §4 مطبَّق حرفيًا بين الأدمن والتطبيق والويب.
- [ ] مفاتيح Tap/FCM/R2 لا تُعرض كاملة ولا تصل إلى أي عميل.

## 7. محاكاة يجب ربطها بالخادم
الأرقام والمؤشرات، الطابور، التحقّق الثنائي، البحث، الإرسال الفعلي عبر FCM، فحص R2، رفع الملفات، المعاينات، أرقام الجمهور ونِسب الفتح.
