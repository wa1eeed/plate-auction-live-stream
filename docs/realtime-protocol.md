# بروتوكول التحديثات اللحظية

> مواصفة اتصال WebSocket على `/ws`.
> الخادم: [`server.mjs`](../server.mjs) + [`src/lib/server/realtime.ts`](../src/lib/server/realtime.ts).
> العميل: [`src/lib/hooks/use-realtime.ts`](../src/lib/hooks/use-realtime.ts).

## 1. المبدأ الحاكم

**الحدث إشعار، لا حالة.**

الحدث الواصل يقول «تغيّر شيء في هذا الموضوع» فقط. العميل لا يبني حالته من
حمولة الحدث، بل يطلب مزامنة كاملة عبر `GET /api/listings/{id}`.

الفائدة: مسار واحد لبناء الحالة. أي حدث ضائع أو انقطاع أو رسالة قديمة لا يترك
العميل على حالة ناقصة، لأن المزامنة التالية تصحّح كل شيء.
راجع [ADR-0005](adr/0005-commands-http-events-websocket.md).

## 2. الاتصال

```
ws://HOST/ws     (wss:// عندما تكون الصفحة https)
```

بلا مصادقة: الأحداث المنشورة عامة أصلًا، ولا تحمل أي بيانات خاصة. كل ما يحتاج
هوية يمرّ عبر HTTP بكوكي الجلسة.

## 3. المواضيع (Topics)

| الموضوع | من يشترك | ماذا يصله |
| --- | --- | --- |
| `listing:{id}` | صفحة إعلان واحد | أحداث ذلك الإعلان + حضور المشاهدين |
| `market` | شبكة السوق | كل أحداث كل الإعلانات |

اتصال واحد يخدم عدة مواضيع، بحدّ **20 موضوعًا** لكل مقبس وطول اسم **≤ 120 حرفًا**.

## 4. رسائل العميل ← الخادم

### `sub` — اشتراك

```json
{ "t": "sub", "topics": ["listing:lst_abc", "market"] }
```

يردّ الخادم بـ `welcome` ثم يبثّ `presence` لمواضيع الإعلانات المضافة.

### `unsub` — إلغاء اشتراك

```json
{ "t": "unsub", "topics": ["listing:lst_abc"] }
```

### `ping` — نبضة

```json
{ "t": "ping" }
```

يردّ `{"t":"pong"}`. يرسلها العميل كل **25 ثانية**. رسالة غير صالحة أو غير
معروفة تُتجاهل بصمت.

## 5. رسائل الخادم ← العميل

### `welcome`

أول ردّ على `sub`، ويحمل آخر رقم تسلسلي لكل موضوع مشترك فيه:

```json
{ "t": "welcome", "seq": { "listing:lst_abc": 12, "market": 340 } }
```

بهذا يعرف العميل نقطة البداية ويكتشف الفجوة من أول حدث.

### `ev` — حدث

```json
{
  "t": "ev",
  "topic": "listing:lst_abc",
  "seq": 13,
  "kind": "bid_placed",
  "payload": { "listingId": "lst_abc", "amount": 18500000, "bidderName": "ماجد ا*****" },
  "at": "2026-08-31T12:03:27.512Z"
}
```

`kind` أحد أنواع `ListingEvent` أو `presence`:

`listing_published` · `bid_placed` · `bid_cancelled` · `time_extended` ·
`auction_ended` · `offer_placed` · `offer_accepted` · `offer_declined` ·
`listing_sold` · `listing_cancelled` · `presence`

الحمولة عامة دائمًا: مبالغ وأسماء مقنّعة، **بلا سعر احتياطي وبلا بيانات تواصل**.

### `presence` — عدد المشاهدين

```json
{ "t": "ev", "topic": "listing:lst_abc", "seq": 14, "kind": "presence",
  "payload": { "viewers": 7 }, "at": "…" }
```

يُبثّ عند كل اشتراك أو إلغاء أو انقطاع على موضوع إعلان. لا يُبثّ لموضوع `market`.
لا يستدعي مزامنة — لا يمسّ بيانات الإعلان.

### `pong`

```json
{ "t": "pong" }
```

## 6. الترقيم التسلسلي وكشف الفجوات

لكل موضوع عدّاد متزايد مستقل في `registry.seq`. مع كل نشر يزيد بواحد.

```
العميل يحفظ آخر seq لكل موضوع
   حدث جديد seq = previous + 1  ⇒  طبيعي  ⇒  مزامنة مجمّعة (200 مللي)
   حدث جديد seq > previous + 1  ⇒  فجوة   ⇒  مزامنة فورية
```

الفجوة تعني حدثًا لم يصل — وهي نقص مؤكَّد في الحالة، فتُزامَن فورًا لا مجمّعة.

## 7. صمود الاتصال

| الآلية | القيمة | الغرض |
| --- | --- | --- |
| مزامنة عند الاتصال | كل `open` | تسدّ ما فات أثناء الانقطاع |
| تجميع المزامنة | 200 مللي | عدة أحداث متتابعة ⇐ طلب واحد |
| نبضة العميل | 25 ثانية | إبقاء الاتصال حيًّا |
| حدّ الصمت | 45 ثانية | بلا أي رسالة ⇐ يُغلق العميل ويعيد الاتصال |
| نبضة الخادم | 30 ثانية | `ping` وإسقاط من لا يردّ `pong` |
| تراجع أُسّي | 1، 2، 4، 8، 15 ثانية + نثر ≤ 400 مللي | يمنع تزاحم إعادة الاتصال |
| السقوط الاحتياطي | بعد 3 محاولات فاشلة | إعادة جلب دورية كل 8 ثوانٍ |
| الاستيقاظ | `visibilitychange` + `online` | مزامنة فورية وإعادة اتصال |

**التجميع مهم للحمل**: بدونه كان كل حدث يُطلق طلب مزامنة من كل مشاهد، فيتضاعف
الحمل مع عدد المشاهدين في اللحظة نفسها.

**السقوط الاحتياطي**: إن تعذّر WebSocket نهائيًا (وسيط شبكة يمنع الترقية مثلًا)
تبقى الصفحة صحيحة عبر إعادة الجلب الدورية — بتأخير أعلى فقط.

## 8. حالات الاتصال في الواجهة

| الحالة | المعنى | العرض |
| --- | --- | --- |
| `connecting` | أول محاولة | «جارٍ الاتصال» |
| `live` | متصل | «مباشر» |
| `reconnecting` | انقطع، أقل من 3 محاولات | «إعادة الاتصال» |
| `offline` | 3 محاولات فأكثر، يعمل بالجلب الدوري | «غير متصل» |

## 9. النشر من كود التطبيق

```ts
import { MARKET_TOPIC, listingTopic, publishRealtime } from '@/lib/server/realtime'

publishRealtime([listingTopic(id), MARKET_TOPIC], 'bid_placed', { listingId: id, amount })
```

عمليًا لا يُستدعى مباشرة: الدالة الداخلية `publish()` في
[`market-service.ts`](../src/lib/server/market-service.ts) تكتب الحدث في السجلّ
الدائم **ثم** تنشره، فلا يوجد حدث مدفوع بلا أثر محفوظ.

مقبس معطوب أثناء البثّ لا يوقف البقية: يُلتقط الخطأ ويُنظَّف المقبس عند إغلاقه.

## 10. مثال كامل

```
العميل                                         الخادم
  │───── GET /ws  (Upgrade) ──────────────────────▶│
  │◀──── 101 Switching Protocols ──────────────────│
  │───── {"t":"sub","topics":["listing:x","market"]} ▶
  │◀──── {"t":"welcome","seq":{"listing:x":0,"market":0}}
  │◀──── {"t":"ev","topic":"listing:x","seq":1,"kind":"presence",…}
  │
  │      … مزايد آخر يرسل POST /api/listings/x/bids …
  │
  │◀──── {"t":"ev","topic":"listing:x","seq":2,"kind":"bid_placed",…}
  │◀──── {"t":"ev","topic":"market","seq":1,"kind":"bid_placed",…}
  │───── GET /api/listings/x  (مزامنة مجمّعة) ─────▶│
  │◀──── ListingDetail ────────────────────────────│
  │
  │───── {"t":"ping"} ────────────────────────────▶│
  │◀──── {"t":"pong"} ─────────────────────────────│
```

## 11. التوسّع الأفقي

السجلّ يعيش في ذاكرة العملية، فالنشر يصل إلى مقابس **هذه النسخة وحدها**. عند
تشغيل أكثر من نسخة يلزم ناقل مشترك:

1. استبدال جسد `publishRealtime` بنشر على Redis pub/sub (أو ما يعادله).
2. اشتراك كل نسخة بالقناة وإعادة البثّ إلى مقابسها.
3. نقل عدّاد `seq` إلى المخزن المشترك ليبقى مرتّبًا عبر النسخ.

الواجهة العامة (`publishRealtime`, `listingTopic`, `MARKET_TOPIC`) لا تتغيّر،
ولا يتغيّر كود العميل.


## قياس حيّ

قِيست دورة كاملة على خادم التطوير: مزايدة أُرسلت من **جلسة خارج المتصفّح**
تمامًا (`curl` بكوكي مستخدم آخر)، وصفحة المزاد مفتوحة بلا لمس.

```
إرسال المزايدة        → t + 0 ms
تغيّر السعر على الشاشة → t + 506 ms
عدد تحديثات الصفحة    → 1 (التنقّل الأصلي وحده)
```

الـ506 مللي تشمل: بثّ الحدث عبر WebSocket، ثم تجميع 200 مللي
(`RESYNC_COALESCE_MS`) يمنع عاصفة طلبات عند تتابع المزايدات، ثم إعادة المزامنة
من REST، ثم التصيير. المسار ليس المسح الاحتياطي (`FALLBACK_POLL_MS = 8s`) —
ذاك لا يبدأ إلا بعد ثلاث محاولات اتصال فاشلة.

يحرس هذا [`tests/e2e/realtime.spec.ts`](../tests/e2e/realtime.spec.ts): يزايد من
سياق متصفّح مستقلّ، ويتحقّق أن السعر تغيّر **وأن عدّاد التنقّل لم يزد** — فلا
تمرّ مزامنة كاذبة سببها تحديث صفحة.
