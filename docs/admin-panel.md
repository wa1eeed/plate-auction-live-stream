# لوحة الإدارة

> صلاحيات المنصّة: المؤشرات، والمستخدمون ومحافظهم، والإعلانات والصفقات
> والعرابين، والأسئلة الشائعة.
> المصادر: [`admin-service.ts`](../src/lib/server/admin-service.ts) ·
> [`src/app/admin/`](../src/app/admin/)

## 1. جلسة مستقلّة — لماذا؟

**كوكي الإدارة `pa_admin` منفصل تمامًا عن كوكي المستخدم `pa_session`.**

هذا ليس تفصيلًا تقنيًا بل متطلّب صريح: أن تكون مسجّلًا في لوحة الإدارة وفي حساب
مستخدم عادي **في المتصفّح نفسه في آنٍ واحد**، وتتنقّل بينهما أثناء التجربة بلا
خروج من أحدهما. جلسة واحدة بدور لكانت أجبرتك على الخروج والدخول مع كل تبديل.

| | جلسة المستخدم | جلسة الإدارة |
| --- | --- | --- |
| الكوكي | `pa_session` | `pa_admin` |
| المدة | 14 يومًا | **8 ساعات** — صلاحياتها أوسع |
| الحارس | `requireUserId` | `requireAdminId` |
| الخروج | لا يمسّ الإدارة | لا يمسّ المستخدم |

## 2. حساب إداري منفصل عن المستخدم

لا يوجد حقل «دور» على `User`. الإدارة كيان مستقلّ `AdminAccount` بجدوله الخاص.

**لماذا؟** ثلاثة أسباب:

1. حقل الدور على المستخدم يتسرّب إلى الحمولات العامة بسهولة.
2. رفع صلاحية مستخدم عاديًا يصير خطأً واردًا (تعديل حقل واحد).
3. الفصل يجعل الجلستين المتوازيتين طبيعيتين لا حيلة.

## 3. الصفحات

| المسار | المحتوى |
| --- | --- |
| `/admin/login` | دخول مستقلّ — خارج الحارس |
| `/admin` | المؤشرات: النشاط، الأموال، الالتزامات، وما يحتاج إجراءً |
| `/admin/users` | كل المستخدمين بأرقام عضويتهم وأرصدتهم ونشاطهم |
| `/admin/users/{رقم العضوية}` | نظرة 360°: رقم العضوية بارزًا قابلًا للنسخ، وبطاقات المحفظة، ومؤشّرات النشاط، ووسوم الحالة، ثم تبويبات النشاط والمال واللوحات والصفقات |
| `/admin/listings` | كل الإعلانات مع الإيقاف |
| `/admin/listings/{رقم الإعلان}` | صفحة الإعلان الإدارية: المزاد وكشفه ومشاركوه وعرابينه وصفقاته، **والاحتياطي ظاهر** |
| `/admin/orders` | الصفقات ومهل السداد والإغلاق |
| `/admin/deposits` | العرابين: المصادرة والردّ — **واللوحة مرسومة لا مكتوبة** |
| `/admin/transactions` | آخر 200 قيد على المحافظ |
| `/admin/revenue` | **إيرادات المنصّة**: عمولات وضرائب وعرابين مُصادَرة، بحالة كلٍّ (محصَّل · مستحقّ · مُبطَل) |
| `/admin/payments` | المدفوعات: تأكيد الحوالات البنكية أو رفضها |
| `/admin/settings` | ثلاثة تبويبات: **قواعد المزاد** (العربون والمهل والمصادرة والتمديد) · **العمولة والضريبة** · **الدفع** (بيئة Tap وبيانات البنك) |
| `/admin/faq` | إضافة وتعديل وحذف الأسئلة |
| `/admin/audit` | سجلّ التدقيق: كل فعل إداري بمنفّذه وحالته قبل وبعد |

**الروابط تحمل الأرقام المرجعية**: صفحة المستخدم تُفتح بـ`/admin/users/U26-00003`
لا بالمعرّف الداخلي، فيتطابق شريط العنوان مع ما في الصفحة ومع ما يراه المستخدم
في حسابه — والأدمن يُملي رقمًا واحدًا لا رقمين. والمعرّف الداخلي يبقى مقبولًا
فلا تنكسر روابط محفوظة.

## 3.5 لا تُدفع الإدارة خارج لوحتها

الضغط على لوحة في أي جدول إداري يفتح **صفحة الإعلان الإدارية** لا صفحة السوق:
الأدمن يريد الكشف والمشاركين والعرابين، لا واجهة المزايدة. وما يقصد به السوق
فعلًا — «عرض السوق» في الترويسة، و«مشاهدة حيّة» في صفحة الإعلان — يفتح في
**نافذة جديدة** (`target="_blank"` مع `rel="noopener"`)، فيعود الأدمن إلى لوحته
بلا فقد سياق ولا رجوع بالمتصفّح.

**ما تزيده الصفحة الإدارية على صفحة السوق**: الأسماء **صريحة** لا مقنّعة لأن
الإدارة تحقّق في نزاع وتحتاج معرفة من زايد؛ و**السعر الاحتياطي ظاهر** لأنه سرٌّ
عن المزايدين لا عمّن يفصل بينهم؛ وتبويب **المشاركين** يجمع لكل مزايد أعلى
مزايداته وحالة عربونه في سطر واحد.

## 3.6 التنقّل

أحد عشر رابطًا في عمود واحد تُقرأ بالبحث لا بالنظر، فجُمّعت في ثلاثة أقسام —
**التشغيل** و**المال** و**النظام** — ويبقى «المؤشرات» فوقها بلا عنوان.

و**شارات حمراء** على الصفقات والعرابين والمدفوعات تحمل عدد ما ينتظر تصرّفًا:
صفقات تجاوزت مهلتها، وعرابين استحقّت المصادرة، وحوالات تنتظر التحقّق. تُحسب في
الخادم مع كل تصيير (`getNavBadges`) فلا تحتاج طلبًا خاصًّا ولا تُصبح قديمة —
وبدونها يفتح الأدمن كل قسم ليتأكّد أن لا شيء فيه.

على الجوال يبقى شريطًا أفقيًا واحدًا: العناوين تُهدر عرضًا ثمينًا هناك.

**بنية المسارات**: صفحات اللوحة داخل مجموعة `(panel)` التي تحمل التخطيط الحارس،
وصفحة الدخول خارجها. التخطيطات في Next تتداخل ولا تُستبدل، فلو كان الحارس على
`/admin` مباشرة لحرس صفحة الدخول نفسها وأنتج إعادة توجيه لا نهائية —
وقد وقع ذلك فعلًا قبل إعادة الهيكلة.

## 4. المؤشرات

ثلاث مجموعات، كل بطاقة رابط إلى تفصيلها:

| المجموعة | المؤشرات |
| --- | --- |
| النشاط | المستخدمون · الإعلانات · المزادات الجارية · المزايدات المقبولة |
| الأموال | المبيعات المكتملة · أرصدة المحافظ · العرابين المحجوزة · المُصادَرة |
| الالتزامات | الصفقات المفتوحة · **تجاوزت مهلة السداد** · المتخلّفة · الإجمالي |

وقسم **«يحتاج إجراءً الآن»** يسرد الصفقات المتأخّرة مباشرة — اللوحة تُقرأ لتُعرف
منها الخطوة التالية لا لتُتأمَّل.

ثلاث لمسات تجعل الرقم يقول شيئًا:

- **شريط نسبة** تحت الرقم حيث تكون النسبة هي المعنى: «25,000 عربونًا محجوزًا»
  وحدها لا تقول شيئًا، وكونها 17٪ من أرصدة المحافظ تقول الكثير.
- **وسم «يستحقّ نظرة»** (نقطة نابضة وحدّ ملوّن) على ما ينتظر تصرّفًا فعلًا —
  لا لون رقم فقط: أربع بطاقات ملوّنة في صفّ تُلغي بعضها.
- **شريط لوني** يسبق عنوان كل مجموعة: ثلاثة عناوين رمادية متتابعة تُقرأ
  كقائمة واحدة طويلة.

## 5. الصلاحيات الإدارية

| الإجراء | الأثر |
| --- | --- |
| شحن رصيد | قيد `topup` في كشف حساب المستخدم |
| خصم رصيد | قيد `withdrawal` — لا يتجاوز المتاح |
| مصادرة عربون | خصم نهائي + الصفقة «متخلّفة» + سبب إلزامي |
| ردّ عربون | إعادة إلى المتاح بلا خصم + سبب إلزامي |
| إتمام صفقة | يخصم عربون المشتري من قيمتها **ويفكّ عرابين بقية المزايدين** |
| إعادة إرساء | صفقة للمزايد التالي بمهلة جديدة، والمصادرة خيار ضمنها |
| تراجع عن مصادرة | خلال مهلتها: يعيد المال، ويُبطل قيد الإيراد، ويعيد الصفقة للانتظار |
| تحصيل عمولة مستحقّة | يقتطعها من المحفظة متى صار فيها ما يكفيها |
| إيقاف إعلان | حالة `suspended` + **فكّ عرابينه** — لا حذف، يبقى الأثر للتدقيق |
| رفع الإيقاف | يعود الإعلان **مسودّة**، والبائع هو من ينشره |
| إدارة الأسئلة | إضافة وتعديل وحذف، وتحديد ما يظهر في صفحة المزاد |
| تأكيد حوالة بنكية | يضيف الرصيد فورًا وينعكس على المستخدم |
| تبديل بيئة Tap | تجريبية أو حقيقية — لا يمكن تفعيل بيئة بلا مفتاح |
| ضبط قواعد المزاد | العربون والمهل والمصادرة والتمديد لكل ما يُنشر بعد الحفظ |
| ضبط العمولة والضريبة | على البائع أو المشتري أو كليهما، وعلى كل ما يكتمل بعد الحفظ |

**السبب إلزامي** في قرارات العربون: القرار يمسّ مال المستخدم، ويظهر له في كشف
حسابه، ويُقيَّد في سجلّ التدقيق باسم من نفّذه.

**المصادرة لا تُتاح إلا بعد انقضاء مهلة السداد، والردّ لا يُتاح ومزايدة صاحبه
قائمة في مزاد جارٍ.** والحراسة **على الخادم** لا في الواجهة: إخفاء زرّ ليس
حراسة، وقد كان طلبٌ مباشر إلى نقطة الإدارة يصادر عربونًا في مزاد جارٍ. الواجهة
لا تشتقّ الشروط بنفسها أصلًا — `listAdminDeposits` ترسل `canForfeit`
و`canRefund` و`canUndo` جاهزة، فلا يظهر زرّ يرفضه الخادم.

**قواعد المزاد مركزية**: العربون والمهل والتمديد تُضبط هنا لا في نموذج البائع،
فالشروط واحدة على الجميع. التفصيل في
[`wallet-and-deposits.md`](./wallet-and-deposits.md#5-قواعد-المزاد--مركزية-لا-لكل-بائع).

## 5.5 الإيقاف والإلغاء ليسا شيئًا واحدًا

| الحالة | من أغلقها | من يعيد عرضها | يُحذف؟ |
| --- | --- | --- | --- |
| `cancelled` | البائع انسحابًا | البائع | نعم (إن لا مزايدات) |
| `suspended` | **الإدارة** لمخالفة | **الإدارة وحدها** | **لا** |

كانتا حالة واحدة، فكان إيقاف الإدارة يُبطله المخالف نفسه: يضغط «إعادة عرض» ثم
«انشر» فتعود اللوحة. إجراء ردع بلا أثر. والفصل بينهما هو ما يجعل بقيّة القواعد
تترتّب وحدها: `suspended` لا يملك البائع رفعها ولا حذف إعلانها.

**كل إغلاق قبل الأوان يفكّ العرابين.** كانت `releaseLosingDeposits` تُستدعى من
موضعين فقط — إتمام صفقة وانتهاء مزاد — والمُغلَق قبل أوانه لا يمرّ بأيّهما، فكان
مال المزايدين يبقى مجمّدًا بلا مزاد خلفه ولا شيء يفكّه.

**إعادة العرض جولة جديدة لا استئناف.** مزايدات الجولة السابقة تُوسَم ملغاة
وتبقى في الكشف، ويعود السعر إلى الافتتاحي، ويصل مزايديها إشعار دعوة برابط
اللوحة — دعوة لا إلزام: من زايد في مزادٍ أُغلق لا يبقى ملزمًا بعرضه في مزاد
جديد قد تمرّ عليه أسابيع.

## 5.6 اللوحة صورة لا نصّ

جداول الإعلانات والعرابين تعرض **رسم اللوحة** لا اسمها: الأدمن يميّزها بلمحة كما
يميّزها صاحبها، و«رر 77» نصًّا لا تقول شيئًا عن الحروف اللاتينية ولا نوع اللوحة.

والنصّ لا يُفقَد — يبقى في `title` وفي `aria-label` — فتبقى اللوحة **مقروءة
لقارئ الشاشة** و**قابلة للبحث** بحروفها وأرقامها رغم أنها صورة.

## 6. سجلّ التدقيق

كل فعل إداري يكتب `AuditLog` بـ `actorId` و`beforeData` و`afterData`:
`wallet.topup` · `wallet.withdrawal` · `deposit.forfeit` · `deposit.refund` ·
`order.status` · `order.reaward` · `listing.cancel` · `faq.create` ·
`faq.update` · `faq.delete` · `payment.paid` · `payment.failed` ·
`payments.settings` · `auction.settings` · `commission.settings` ·
`deposit.forfeit.undo` · `platform.settle`.

## 6.4 محاذاة الجداول

عمود الجدول يُعلَن **مرّة واحدة** في `columns` على `AdminTable`، فتُبنى منه
الترويسة والمحاذاة والعرض معًا:

```tsx
<AdminTable
  minWidth="60rem"
  columns={[
    { label: 'المستخدم', width: '26%', minWidth: '14rem' },
    { label: 'الرصيد', numeric: true, width: '11%', minWidth: '7rem' },
  ]}
>
```

قبل ذلك كان العنوان يحمل محاذاته والخلية محاذاتها، فتنزاح الأرقام عن عناوينها
كلّما نسي أحدهما — وكان العنوان `text-right` **فيزيائيًا** بينما الخلية
منطقية. الآن كلاهما يُخرج `data-align`، وقاعدة CSS واحدة في
[`globals.css`](../src/app/globals.css) تحكمهما، فيستحيل الانزياح.

والمحاذاة **منطقية** (`start`/`end`) لا فيزيائية: اللوحة عربية بالكامل
(`dir="rtl"`)، و`start` أوّل السطر في اتجاه القراءة أيًّا كان. والأعمدة الرقمية
`numeric` تُحاذى نهايةً بأرقام متساوية العرض، فتُقرأ آحادها تحت آحاد ما فوقها.

`width` على `<colgroup>` لا في `className`: يُثبّت العمود بدل أن يتمدّد على
حساب جاره، و`minWidth` يمنع انكماشه تحت محتواه.

## 6.5 البحث في الجداول

**الرقم المرجعي يُطابَق تامًّا لا كجزء من نصّ**: البحث بـ«#1» في جدول فيه
عشرون إعلانًا كان يسرد 1 و10 و11 حتى 19، لأن المطابقة كانت على النصّ. الآن
`TableSearch` يقرأ `#N` ويقارن الرقم نفسه، ويبقى ما عداه بحثًا نصّيًا.

كل جدول إداري فوقه بحث فوري يعمل على الصفوف المُصيَّرة لا بطلب جديد: الجداول
محدودة (200 سطر سقفًا)، والبحث بلا انتظار شبكة أنفع من طلب لكل حرف. ويخفي
الصفوف بـ`display:none` بدل إزالتها فلا يُعاد بناء الجدول مع كل ضغطة.

## 7. الأسئلة الشائعة

| الحقل | الأثر |
| --- | --- |
| `published` | يظهر في `/faq` |
| `showOnListing` | يظهر **أيضًا** أسفل صفحة كل مزاد |
| `category` | عام · المزايدة · العربون · السداد · البيع |
| `sortOrder` | ترتيب العرض تصاعديًا |

الفصل بين العلمين مقصود: صفحة المزاد ليست مكانًا لكل الأسئلة، بل لما يحتاجه
المزايد **قبل أن يضغط زرّ المزايدة** — الاحتياطي، العربون، السداد.

## 8. الواجهة البرمجية

| المسار | الوظيفة |
| --- | --- |
| `POST /api/admin/auth/login` | دخول (5 محاولات/دقيقة) |
| `POST /api/admin/auth/logout` | خروج الإدارة وحدها |
| `POST /api/admin/users/{id}/wallet` | شحن أو خصم |
| `POST /api/admin/deposits/{id}` | `{ decision: 'forfeit' \| 'refund' \| 'undo_forfeit', reason }` |
| `PATCH /api/admin/orders/{id}` | `{ status: 'completed' \| 'cancelled' \| 'defaulted' }` |
| `GET POST /api/admin/orders/{id}/reaward` | خيارات إعادة الإرساء وتنفيذها |
| `POST /api/admin/platform-entries/{id}` | تحصيل عمولة مستحقّة |
| `GET PATCH /api/admin/settings/auction` | قواعد المزاد |
| `GET PATCH /api/admin/settings/commission` | العمولة والضريبة |
| `GET PATCH /api/admin/settings/payments` | بوابات الدفع |
| `DELETE /api/admin/listings/{id}` | إيقاف إعلان |
| `GET POST /api/admin/faq` | قراءة وإضافة |
| `PATCH DELETE /api/admin/faq/{id}` | تعديل وحذف |
| `GET /api/faq?scope=listing` | عام — الأسئلة المنشورة |

كلها تمرّ بـ `requireAdminId()` الذي يتحقّق من **وجود الحساب** لا من توقيع
الجلسة وحده: الكوكي يبقى صالح التوقيع بعد حذف الحساب.
