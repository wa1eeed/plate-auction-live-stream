# ADR-0002: تمثيل المال بأعداد صحيحة من الهللات

**الحالة**: مقبول

## السياق

مبالغ حقيقية تُقارَن وتُجمَع في كل مزايدة: «هل هذا المبلغ ≥ أعلى مزايدة +
الحد الأدنى للزيادة؟». حساب مالي خاطئ بهللة واحدة يعني مزايدة مرفوضة ظلمًا أو
مقبولة خطأً.

`0.1 + 0.2 === 0.30000000000000004` في IEEE 754.

## القرار

كل المبالغ داخليًا `Halalas`: عدد صحيح من الهللات (1 ريال = 100 هللة).
التحويل عند الحدود فقط:

| الحدّ | التحويل |
| --- | --- |
| إدخال المستخدم | `riyalsToHalalas` / `parseAmountInput` |
| العرض | `formatAmount` / `halalasToRiyals` |
| PostgreSQL `numeric(14,2)` | `numericToHalalas` / `halalasToNumeric` |

الواجهة البرمجية تستقبل **ريالات صحيحة** من العميل وتعيد **هللات**: الإدخال
بالريالات لأنه ما يكتبه المستخدم، والإخراج بالهللات لأنه وحدة الحساب الداخلية.

## بدائل مرفوضة

**أعداد عشرية**: أخطاء تقريب متراكمة في المقارنات.

**`BigInt`**: يحلّ الدقة لكن يعقّد التسلسل إلى JSON بلا حاجة — `Number.MAX_SAFE_INTEGER`
يغطّي 90 تريليون ريال.

**مكتبة عشرية** (decimal.js): اعتماد إضافي لمسألة يحلّها عدد صحيح.

## النتائج

كل حساب دقيق تمامًا. الثمن: يقظة عند كل حدّ جديد — قيمة بالريالات تدخل مسارًا
يتوقّع هللات تعني خطأً بمعامل 100. لذلك النوع `Halalas` مسمّى صراحةً، والدوال
تحمل الاتجاه في اسمها.
