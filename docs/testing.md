# استراتيجية الاختبار

> ما يُختبر، وبأي مستوى، ولماذا.
> 338 اختبار وحدة (Vitest) + 95 اختبارًا شاملًا (Playwright).

## 1. التقسيم

| المستوى | الأداة | يغطّي | لا يغطّي |
| --- | --- | --- | --- |
| وحدة | Vitest | القواعد النقية، الخدمات فوق مخزن مبذور، النشر اللحظي | المتصفّح، التصيير |
| شامل | Playwright | رحلات المستخدم الحقيقية عبر مبنى إنتاج | الحالات الحدّية الدقيقة |

القاعدة: **كل قاعدة عمل تُختبر كوحدة**، والاختبار الشامل يثبت أن الأجزاء
موصولة فعلًا. الحالات الحدّية لا تُلاحَق في المتصفّح — أبطأ وأهش.

## 2. التشغيل

```bash
pnpm test        # وحدات، ~4 ثوانٍ
pnpm test:watch  # أثناء التطوير
pnpm test:e2e    # شامل — يبني ويشغّل الخادم تلقائيًا
```

الاختبار الشامل يشغّل `pnpm build && PORT=3100 pnpm start`، أي **الخادم المخصّص
نفسه** الذي يعمل في الإنتاج بمبنى إنتاج حقيقي. هذا مقصود: بيئة التطوير لن
تكشف عطلًا يظهر في المبنى فقط.

يبني في `.next-e2e` لا في `.next` (عبر `NEXT_DIST_DIR`)، فلا يستبدل ملفات خادم
تطوير عامل. بلا هذا العزل كان الخادم العامل يصير يشير إلى حُزم حُذفت، فترجع
404 ويظهر الموقع بلا تنسيق ولا تفاعل.

## 4. الاختبارات الشاملة

| السيناريو | يثبت |
| --- | --- |
| التصفّح العام بلا تسجيل | السوق مفتوح، والتداول يطلب حسابًا |
| المزايدة من صفحة الإعلان | المزايدة تُسجَّل وتظهر في «مزايداتي» |
| الشراء المباشر بين مستخدمين | الصفقة تظهر في «مشترياتي» وفي «مبيعات» البائع |
| عرض يُرسل ويقبله البائع | القبول يُغلق اللوحة |
| إضافة لوحة ونشرها | مسار البائع كاملًا حتى ظهورها في السوق |
| صفحات الحساب على الجوال | لا تمرير أفقي عند عرض 380px |
| لوحة الإدارة محميّة | لا تُفتح بلا تسجيل |
| **الجلستان المتوازيتان** | الإدارة والمستخدم معًا في متصفّح واحد، وخروج أحدهما لا يمسّ الآخر |
| شحن رصيد من الإدارة | يظهر فورًا في محفظة المستخدم وكشف حسابه |
| إضافة سؤال شائع | يظهر في الصفحة العامة |
| المحفظة وشريط الجوال | الرصيد والمحجوز والمتاح، والشريط الثابت لا يغطّي المحتوى |
| إعدادات الدفع | لا تُفعَّل Tap بلا مفتاح، ولا يُطلب مفتاح في أي حقل |
| **مسار الحوالة كاملًا** | المستخدم يطلب ← يرى بيانات الحساب والمرجع ← يبلّغ ← الأدمن يؤكّد ← يُضاف الرصيد |
| **حالات المسار السبع** | بذرة «مشترياتي» تغطّي كل حالة من حالات الشريط، فيُرى العمل بلا صنع الحالة يدويًا |
| **صوت البائع** | «مبيعاتي» تقول «وصل مبلغ المشتري» و«صافي ما يصلك» — ولا تقول «اشتريت» ولا «وصل مبلغك» |
| **مسار الضمان في الواجهة** | السداد يحجز فيقرأ المشتري «المبلغ محجوز» بلا زرّ يخصّه، والبائع يرفع إثبات النقل، فتتحقّق الإدارة وتحوّل المبلغ — والسطر المالي عند المشتري ينقلب إلى «ذهب المبلغ إلى البائع» فلا يبقى يقرأ جملة الحجز |
| **الاعتراض** | يوقف تحويل المبلغ، ويظهر في الإدارة بقرارَين لا ثالث لهما: «حوّل للبائع» أو «أعد للمشتري» |
| العدّاد | كتل الأرقام وشريط التقدّم، وحركته الفعلية خلال ثانيتين |
| الصفحة الرئيسية | البطل والخلاصات الثلاث، وروابطها إلى السوق مفلترًا |
| **لا شفافية صفر في مخرجات الخادم** | حارس ضدّ عودة الصفحة البيضاء عند تعطّل جافاسكربت |
| الفلاتر والدُرج | الشرائح تصفّي فعلًا، والدُرج يطبّق ويُظهر رقاقته |
| التنقّل | دُرج الجوال يُغلق عند الانتقال، ولا تمرير أفقي عند 375/768/1440 |
| لوحة الحساب | المحفظة والأرقام والأقسام |
| **الإشعار اللحظي** | تجاوز مزايدة ← «يحتاج تصرّفك» + عدّاد الجرس + الإشعار في القائمة |
| سجلّ التدقيق | يعرض الفعل ومنفّذه، والبحث يقلّص النتائج ويعيدها |
| **المزاد لحظي** | مزايدة من سياق متصفّح مستقلّ تُغيّر السعر والكشف، **وعدّاد التنقّل لا يزيد** — فلا تمرّ مزامنة كاذبة سببها تحديث صفحة |
| تنقّل الإدارة | مجمَّع بعناوينه، ورابط السوق `target="_blank"`، واللوحة تفتح الصفحة الإدارية لا السوق |
| صفحة الإعلان الإدارية | تبويباتها الأربعة، والاحتياطي ظاهر، ورابط المشاهدة الحيّة في نافذة جديدة، وتُفتح بالرقم وبالمعرّف |
| **صفحة السداد** | البريك داون كامل بالعمولة والضريبة، والمجموع مطابق للطرح، والمعطّلة تُعرض بسببها |
| **السداد من المحفظة** | يُتمّ الصفقة وينقل إلى صفحة الشكر، ومنها «عرض الطلب» |
| **الحوكمة الموحّدة** | نموذج الإدراج يعرض قواعد المنصّة ولا يُتيح تحرير حقل منها، وتغييرها من الإدارة ينعكس على ما يراه البائع |
| قوائم الحروف | ثلاث قوائم بالحرف ومقابله اللاتيني، وقفل ما بعد الفارغ، وإسقاط ما بعد المُفرَغ |
| فلترة عدد الحروف والأرقام | تقلّص النتائج، ورقاقتها تُعيدها، ولوحات النتيجة تحمل العدد المطلوب |
| اللوحة في البطاقة | الدراجة بلا شعار أوسط، وارتفاعات موحّدة، وترتيب لوحة ← عدّاد ← سعر |
| **كشف المزايدات** | ختم `<time dateTime>` بصيغة ISO، ونصّه بتوقيت جهاز القارئ لا الخادم |
| **العمولة قبل الالتزام** | تظهر للمشتري قبل الشراء، وتُقتطع عند الاكتمال، وتُقيَّد في «الإيرادات»، وتظهر خصمًا في كشفه |
| إعدادات العمولة | معطّلة ابتداءً، ومعاينتها تُظهر الأثر على أسعار حقيقية قبل الحفظ |
| **حراسة المصادرة على الخادم** | طلب مباشر يتجاوز الواجهة يُرفَض 409 — الحارس في الخدمة لا في إخفاء الزرّ |
| الوصول بلوحة المفاتيح | أوّل تبويب يقود إلى «تخطّي إلى المحتوى»، ولوحة الإدارة تحمل معلَم `main` |
| **الأرقام المرجعية** | تظهر في البطاقة وصفحة الإعلان وجدولَي الإدارة، ولا تتغيّر بين البطاقة وصفحتها |
| البحث بالرقم | «L26-00043» و«l2600043» تجدان الإعلان وحده، و«4040» تبقى بحثًا في أرقام اللوحة |
| مراجع الكيانات المالية | الصفقات والعرابين والحركات والقيود، كلٌّ بصيغته في جدوله وفي كشف الحساب |
| خصوصية رقم العضوية | `seller` في الحمولة العامة اسمٌ ومدينة وتاريخ عضوية فقط |

سيناريوهات عدّة تستخدم سياقَي متصفّح مستقلين (بائع ومشترٍ، أو إدارة ومستخدم)
لأن هذه المسارات تحتاج طرفين حقيقيين لا تبديل جلسة.

## 4.5 جلسة واحدة للتشغيل كلّه

حدّ معدّل الدخول (الإدارة 5 محاولات/دقيقة) يعمل بحقّ. وكل ملفّ اختبار يخزّن
كوكيه وحده يعني دخولًا حقيقيًا لكل ملفّ — وخمسة ملفّات تستنفد الحدّ فتفشل
المتأخّرة بـ429، والعيب في الاختبار لا في الحدّ.

[`tests/e2e/support/session.ts`](../tests/e2e/support/session.ts) وحدة واحدة
يتشاركها الجميع (`workers: 1`)، فيقع دخول واحد للتشغيل كلّه. ومن خرج عمدًا في
اختباره ينادي `forgetAdminSession()` فلا يبقى كوكي مُبطَل في المخزَن.

## 5. دروس من أخطاء وقعت فعلًا

هذه ليست نظرية — كل بند أسقط اختبارًا أو أخفى عطلًا في هذا المشروع:

**`isVisible()` و`count()` لا تنتظران.** تعيدان الحالة اللحظية فتفشلان مع
المحتوى غير المتزامن. الصواب `await expect(locator).toBeVisible()` الذي ينتظر.

**الوضع الصارم يرفض المحدّد المتعدّد.** نصّ يظهر في أكثر من عنصر (مثل رقم
اللوحة في SVG وفي العنوان) يحتاج `.first()` أو محدّدًا أدقّ.

**فحص التسريب بالنصّ الفرعي يعطي إيجابيات كاذبة.** اختبار «الرقم غير موجود في
الحمولة» فشل حين صادف تساوي سعرين. البديل: قائمة بيضاء للمفاتيح.

**بيانات البذرة تحتاج انتقاءً واعيًا.** اختبار مزايدة اختار مستخدمًا كان أصلًا
صاحب أعلى مزايدة فرُفض بـ `ALREADY_HIGHEST`. الحل مساعد `pickBidder()` يختار
مزايدًا صالحًا.

**عنوان يتكرّر في التذييل يكسر محدّدًا كان يعمل.** إضافة تذييل فيه عمود
«السوق» جعلت `getByRole('heading', { name: 'السوق' })` يطابق عنصرين. تحديد
`level: 1` يفصل عنوان الصفحة عن عناوين التذييل.

**حدّ معدّل الدخول يُسقط الاختبارات المتأخّرة.** دخول الإدارة محدود بخمس
محاولات في الدقيقة — وهو حدّ صحيح لا عيب فيه. ستّة اختبارات تسجّل الدخول
بالحساب نفسه تستنفده، فيفشل السادس بـ429 بلا سبب ظاهر. الحلّ تسجيل دخول واحد
وحقن الكوكي بعده، فنختبر الميزات لا آلية الدخول.

**`page.request` في Playwright لا يحمل كوكي الجلسة.** طلب إداري عبره يعود
`401` بينما الصفحة نفسها مسجّلة الدخول. الطلب من داخل الصفحة
(`page.evaluate` + `fetch`) يحمل الكوكي.

**تنسيق العدّاد يتبع القرب.** اختبار «هل يتحرّك العدّاد؟» على مزاد أمامه يومان
يفشل: الصيغة المضغوطة تعرض الأيام والساعات بلا ثوانٍ عمدًا. تُرصد الحركة على
صفحة الإعلان حيث تظهر الثواني دائمًا.

**اختبر المبنى لا وضع التطوير.** استدعاء مسار محذوف بقي في مكوّن ولم يظهر إلا
في الاختبار الشامل.

**نصّ متبقٍّ من ميزة محذوفة لا يكسر شيئًا فلا يظهر في أي اختبار.** صفحة 404 بقيت
تقول «تأكد من صحة معرّف الغرفة» بعد حذف الغرف بالكامل. عند حذف ميزة، ابحث عن
مصطلحاتها في النصوص الظاهرة لا في الكود وحده.

### الحارس في الواجهة ليس حارسًا

`forfeitDeposit` كانت لا تفحص إلا أن العربون `held`. والواجهة تُخفي الزرّ قبل
انقضاء المهلة، والتوثيق يقول «والخادم يحرس القاعدة نفسها» — ولم يكن يحرسها.
طلبٌ مباشر واحد صادر عربونًا في مزاد جارٍ لا صفقة له.

الدرس مزدوج: **كل شرط تعرضه الواجهة يُفرَض في الخدمة**، و**الادّعاء في
التوثيق لا يُصدَّق بلا اختبار يثبته**. الآن اختبار وحدة لكل رمز رفض، واختبار
شامل يرسل الطلب متجاوزًا الواجهة تمامًا.

### الأثر المكتوب مرّتين يُنسى مرّة

اكتمال الصفقة كان في مسارين — البائع والإدارة — فحمل مسار الإدارة آثاره
المالية الثلاثة ونسيها مسار البائع، فبقيت عرابين المزايدين محجوزة إلى الأبد
كلّما أغلق بائع صفقته بنفسه. لم يكشفه اختبار لأن الاختبارات كلّها كانت تمرّ
بمسار الإدارة.

القاعدة: **إن كان للفعل مساران، فليكن له تنفيذ واحد يستدعيانه** — وإلا فاختبر
المسارين كليهما.

### تلوّث الحالة بين الاختبارات الشاملة

اختبار العمولة كان يشتري لوحة **مبذورة**، فتُغلق وتختفي من السوق، فيفشل اختبار
البحث في ملفّ آخر يعتمد عليها. والفشل ظهر في اختبار بريء لا علاقة له بما
تغيّر.

القاعدة: **الاختبار الذي يستهلك موردًا يُنشئه بنفسه.** الآن ينشئ البائع لوحته
الخاصة عبر الواجهة البرمجية ثم يشتريها المشتري.

### إشعار سابق يُطابق لاحقًا

`getByText('حُفظت قواعد المزاد')` بعد حفظين متتاليين يجد إشعارين فيسقط بـ
strict mode — و`.first()` يُخفي العيب لا يُصلحه: يطابق الإشعار **الأول** فتمرّ
الحالة ولو فشل الحفظ الثاني.

القاعدة: **تحقّق من الأثر لا من الإشعار.** الاختبار الآن يُعيد تحميل صفحة
البائع ويقرأ القيمة المستعادة.

## 6. ما يجب أن يبقى مغطّى

عند أي تعديل، هذه أهم تغطية لا يجوز فقدها:

1. **عدم تسريب السعر الاحتياطي** — قائمة بيضاء لمفاتيح `ListingDetail`.
2. **رفض المزايدة على النفس** وعلى إعلان مغلق أو منتهٍ.
3. **الذرّية** — شراء متزامن لا ينتج طلبين.
4. **منع التكرار** — `clientRequestId` نفسه لا يسجّل مزايدتين.
5. **التسلسل لكل موضوع** — أساس كشف الفجوات في العميل.
6. **قبول العرض** يُغلق الإعلان ويرفض بقية العروض.
7. **تقييد المزايدة بالعربون** — رفض بلا تسجيل مزايدة ولا عربون معلّق.
8. **تسوية العرابين** — فكّ الخاسرين، ومصادرة المتخلّف، وخصم المُتمّ.
9. **عزل جلسة الإدارة** عن جلسة المستخدم.
10. **منع الشحن المزدوج** — تأكيد متكرّر ينتج قيدًا واحدًا.
11. **رفض ويبهوك بتوقيع مزوّر** أو حمولة عُبث بمبلغها.
12. **لا عنصر يُرسَل بشفافية صفر** — الصفحة تُقرأ بلا جافاسكربت.
13. **الإشعار لا يُسقط العملية** ولا يصل مستخدمًا آخر.
14. **الحُرّاس في الخدمة**: طلب مباشر يتجاوز الواجهة يُرفَض — مصادرة قبل
    المهلة، أو على عربون بلا صفقة، أو ردٌّ لمزايدة قائمة.
15. **مسار اكتمال واحد**: إغلاق البائع لصفقته يفعل ما يفعله إغلاق الإدارة —
    خصمًا وفكًّا واقتطاعًا للعمولة.
16. **الضريبة على العمولة وحدها** لا على قيمة اللوحة.
17. **العمولة تُعرض قبل الالتزام** لا بعده.
18. **محاذاة الجداول**: عنوان كل عمود وخليّته يخرجان من إعلان واحد.

## 7. إضافة اختبار

```ts
// tests/unit/…: مخزن نظيف وحدود معدل نظيفة لكل حالة
import { emptyDatabase, MemoryStore } from '@/lib/store/memory-store'
import { seedDatabase } from '@/lib/store/seed'
import { resetStoreForTests } from '@/lib/store'
import { resetRateLimits } from '@/lib/server/rate-limit'

beforeEach(() => {
  db = emptyDatabase()
  seedDatabase(db)
  store = new MemoryStore(db)
  resetStoreForTests(store)   // الخدمات تقرأ المخزن من globalThis
  resetRateLimits()           // وإلا سرّبت حالة عدّاد المعدل بين الاختبارات
})
```

`resetRateLimits()` ضروري: عدّاد المعدل يعيش على `globalThis` فيتسرّب بين
الاختبارات، وبلا تصفيره تفشل الاختبارات المتتابعة على الإعلان نفسه بـ
`RATE_LIMITED` بمجرّد تجاوز الحدّ داخل النافذة.

للقواعد النقية استورد من `@/lib/domain/*` مباشرة بلا مخزن.

أسماء `describe` و`it` بالعربية اتّساقًا مع لغة المشروع، ومخرجات الاختبار
تُقرأ كوصف للسلوك.
